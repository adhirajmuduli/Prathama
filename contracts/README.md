# Trendsmapp contracts

This directory holds the machine-readable contract artifacts of the rebuilt
backend. A contract is the agreement between the API, the worker, the
frontend, and any external consumer. Everything in this directory is
generated from the code, committed, and verified in CI, so a contract change
cannot reach a release without a reviewable diff.

## Contents

| File | Purpose | Generated by |
| --- | --- | --- |
| `openapi.v1.json` | OpenAPI snapshot of the HTTP API for API major version 1 | `backend/scripts/export_openapi.py` |
| `schema-versions.json` | Contract versions this build speaks | `backend/scripts/export_schema_versions.py` |
| `examples/*.json` | The exact payloads a client receives | `scripts/verify_contract_examples.py` |

## Versioning policy

The API is versioned by a **major** number in the path (`/api/v1`). A major
version changes only when an existing client would break: a removed endpoint,
a renamed field, a changed unit, a changed error code, or a changed meaning of
an existing field. Additive changes inside a major version are allowed, and
every additive change must update `openapi.v1.json` and the examples.

Schema artifacts carry a `MAJOR.MINOR.PATCH` version. A minor bump means an
additive change; a major bump means a consumer must change its reader.
Recipes are the request documents of the scientific API and are versioned the
same way.

The current versions live in `backend/src/trendsmapp/contracts/versions.py`
and are exported to `schema-versions.json`. The API rejects an unknown
**major** version with a `409` error and a structured reason; an unknown minor
version is accepted and recorded in the run manifest.

## Compatibility rules

1. A request is rejected when its declared major version is not supported.
2. A response never removes a field that a documented client may read.
3. Every error response uses the same envelope: `error.code`,
   `error.message`, optional `error.details`, and `request_id`.
4. Every response carries `X-Request-ID`, which matches the `request_id` in
   the error envelope and in the server log line of the same request.
5. Units are explicit. A field never changes unit without a major bump of
   the owning schema.

## Regenerating and verifying

```bash
# Write the snapshots and the examples.
make contracts-export

# Fail when a committed artifact no longer matches the code.
make contracts-check
```

`make contracts-check` runs three independent checks:

- the OpenAPI snapshot still describes the current application;
- `schema-versions.json` still matches the constants in the code;
- every committed example still equals the payload the running API returns.

The example check starts the application in-process with a temporary database
and a temporary object store, requests each documented endpoint, and compares
the response with the committed JSON. A new endpoint therefore cannot be
added without also committing its example.
